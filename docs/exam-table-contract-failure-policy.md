# 표 계약 위반 처리 정책

Part 4 표(`tableContext`)가 서버 계약을 어겼을 때 웹이 어떻게 행동하는지, 왜 그렇게
정했는지 적어 둔다.

## 1. 계약 위반은 하나라도 있으면 치명적으로 본다

`mapExamTableContext`는 표를 끝까지 매핑하면서 어긋난 지점을 `issues`로 모은다. 이때
구조가 아예 깨진 경우(`invalid-context`)만 실패로 돌려주고, `duplicate-column` ·
`missing-cell` · `extra-cell` · `invalid-scalar` 같은 위반은 fallback 값(`—` 등)으로
메운 뒤 `ok: true`와 함께 돌려준다.

`toExamTableSlot`은 **`issues`가 비어 있을 때만** 표를 통과시킨다.

- 표는 응시자가 답변 근거로 읽는 데이터다. 열이 중복되거나 셀이 빠진 표를 "복구했다"고
  치고 그리면, 서버가 보낸 것과 다른 내용을 응시자가 사실로 읽는다.
- 개별 fallback 로직은 매퍼에 그대로 남겨 둔다. 어디가 어떻게 어긋났는지 issue 경로까지
  보고하려면 끝까지 매핑해 봐야 하기 때문이다.
- 판정은 `src/features/exam/map-exam-table-context.test.ts`가 코드별로 고정한다.

앱(app-front-end)은 같은 위반에서 예외를 던져 Part 4 진입 자체를 막는다. 웹은 화면마다
할 수 있는 일이 달라서 아래처럼 갈린다.

## 2. 화면별 동작

| 화면                   | 동작                                           | 이유                                                                  |
| ---------------------- | ---------------------------------------------- | --------------------------------------------------------------------- |
| 응시 (`/exam/session`) | 시험을 **시작하지 않는다**. 안내 화면 + 홈으로 | 읽을 수 없는 문제는 답할 수도 없다                                    |
| 문제별 피드백          | 표 자리에 안내만 띄우고 나머지 피드백은 그대로 | 이미 끝난 답변을 보여 주는 화면이라 표 하나로 전체를 막을 이유가 없다 |

응시 화면은 세션 응답을 받은 직후(`findUnpresentableQuestions`) 모든 문제를 검사한다.
세션 응답은 응시 도중 바뀌지 않으므로, 여기서 통과한 세션은 진행 중에 같은 이유로 표를
잃지 않는다. `ExamTable`의 안내 문구는 이 검사를 지나쳐 온 경우의 마지막 안전망이다.

## 3. 응시권 — 아직 남은 문제

시작을 막는 이유의 절반은 **회차 손실**이다. 표를 못 읽는 채로 시험을 진행하면 응시자는
Part 4를 못 푼 채 회차만 쓰고, 결제가 붙으면 그대로 응시권 손실이 된다.

다만 지금 프런트가 막을 수 있는 건 "시작하지 않는 것"까지다. 세션 생성
(`POST /api/v1/exams`) 요청은 이미 서버로 나간 뒤이고, 그 요청이 회차를 소진시키는지는
백엔드 정책이다. 그래서 안내 문구도 "응시권이 차감되지 않는다"고 말하지 않고 "답변은
진행되지 않았다"까지만 말한다.

**결제를 붙이기 전에 필요한 것**

- 생성된 세션을 소진 없이 되돌리는 백엔드 엔드포인트(예: `POST /api/v1/exams/{id}/cancel`).
  기존 `terminateExam`은 제출된 답변으로 채점을 요청하는 API라 이 용도로 쓸 수 없다 —
  답변 0개짜리 채점 결과가 남고 회차도 그대로 소진된다.
- 그 엔드포인트가 생기면 `src/app/exam/session/page.tsx`의 차단 지점에서 호출하고,
  안내 문구를 "응시권은 차감되지 않았어요"로 바꾼다.

## 4. 관측

차단은 응시자에게 안내 화면만 남기고 조용히 끝난다. 서버 데이터가 언제부터 어긋났는지는
`reportExamSessionBlocked`가 Sentry로 보내는 `EXAM_SESSION_UNPRESENTABLE`만 남는다.
`reportSummaryFeedbackIssue`와 같은 이유로 examId 같은 식별자는 싣지 않고, 파트·문제
번호와 사유만 보낸다.
